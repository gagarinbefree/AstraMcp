# Реальная проверка Астры через MCP, 01.11.2026

**Восемь из восьми заказов прошли проверку.** Клиент — официальный .NET MCP SDK 2.3.0, сервер — опубликованный Windows x86 AstraMcp, движок — установленный `C:\Program Files (x86)\Astra R-Nesting\Astra.exe`. Node-клиент не использовался.

Путь выполнения: `validate_order → submit_order → SQLite-очередь → Astra.exe -i -n -q → get_job → get_result → XML-ресурс`. Для каждого заказа проверен повтор запроса с тем же ключом. Восемь процессов Астры имели разные PID, интервалы их расчётов не пересекались. Имя результата сверяется с уникальным именем задания.

Для всех 54 размещённых деталей XML содержит координаты. Отдельный верификатор проверил границы листов, отсутствие пересечений и достаточность зазора под пропил между деталями с пересекающимися проекциями. Для 95 отрезков резов проверены границы листа и параллельность координатным осям. Длина сегментов вычисляется из координат, независимо от поля `cut_length`. Количества учитывают повторения карт.

Сохранённые исходники совпадают с переданными заказами. Байты файлов `result.astra.xml` совпадают с экспортом Астры; файлы остаются в исходной кодировке Windows-1251. Тексты XML, прочитанные через MCP-ресурсы, также совпадают с декодированными сохранёнными файлами. SHA-256, PID и времена выполнения перечислены в [машиночитаемой проверке](contracts/native-verification-2026-11-01.json).

Общий отчёт клиента — `report.json`, дополнительная проверка сохранности и последовательности — `verification.json`. Для каждого заказа есть входной XML, `result.astra.xml`, манифест, статус, лог и `geometry.json`.

## Что исправлено при реальном прогоне

Первоначально командный запуск читал старые параметры: экспорт при выходе был выключен, а база и каталог обмена указывали на прежние пути. Параметры в окне Астры и эффективный профиль командного запуска различались. После настройки legacy-профиля `HKCU\Software\Technos\Астра Раскрой\Settings` экспорт заработал. Это воспроизводит [scripts/configure-astra-profile.ps1](../scripts/configure-astra-profile.ps1), сохраняющий прежние значения перед изменением.

Первый прогон всех заказов дал 7/8: случай с запрещённым поворотом упёрся в модальное сообщение о неразмещённой детали. MCP завершил принадлежащий ему процесс по тайм-ауту и продолжил очередь. Включена штатная настройка «Не сообщать о проблемах при раскрое» (`NestTrouble=1`). После этого восемь заказов прошли два полных прогона; последний включает независимую проверку геометрии. Частичные результаты остаются видны в отчётах, проверка спроса не отключена.

В `config.json` установлено `ProfileReady=true`. Предыдущий запрет на запуск Астры отменён явным разрешением пользователя. Обработка выполнялась без дополнительных ручных действий после настройки профиля.

## Повторный запуск

При закрытой Астре из корня репозитория:

```powershell
.\scripts\configure-astra-profile.ps1 -ConfigurationFile config.json
dotnet run --project tools/Verification/Verification.csproj -- . config.json
```

Один выбранный заказ: добавьте его идентификатор последним аргументом, например `04-rotation-required`. Каждый запуск создаёт новый каталог результатов. Обычные автоматические тесты запускаются отдельно и установленную Астру не используют; после добавления верификатора геометрии проходят **72 теста**, включая этапы red/green.

Этот прогон не доказывает оптимальность раскроя или технологическую выполнимость дерева гильотинных резов. Кромки и дробная точность в восьми заказах не проверялись. Верификатор не восстанавливает отсутствующие координаты и явно сообщает их покрытие; в этом прогоне оно полное.
