# Проверка MCP, 01.11.2026

Проверено 64 автоматических теста: 64 прошли, 0 ошибок, 0 пропущенных. Отдельно выполнены пять проверок MCP Inspector 2.13.0 на опубликованном Windows x86 приложении: обнаружение шести инструментов, правильный XML, ошибка на неправильном XML, возможности сервера и шаблон ресурсов.

[Машиночитаемый отчёт](contracts/mcp-verification-2026-11-01.json) содержит пути к TRX и сохранённым манифестам. Исходные заказы — [examples/batch](../examples/batch/README.md): восемь файлов, 56 запрошенных физических деталей. Все восемь прошли `validate_order` по MCP stdio.

На этом этапе сквозной прогон использовал настоящий MCP-клиент, сервер в отдельном процессе, SQLite-очередь и отдельный тестовый `NativeFixture.exe`. Он воспроизводил известный экспорт Астры с уникальным именем задания и управляемыми ошибками. Установленная Астра тогда не запускалась по указанию пользователя. После отдельного разрешения выполнен [реальный прогон восьми заказов](native-verification.md) через официальный .NET-клиент; описанные ниже результаты относятся к ранней проверке с fixture.

| Проверка | Результат |
| --- | --- |
| Три задания в одной очереди | Все завершены последовательно, без наложения интервалов выполнения |
| Повтор одного запроса | Возвращает прежний jobId |
| Другой XML с прежним ключом | Возвращает ошибку |
| Выходной результат | 1 лист, 2 детали для каждого воспроизведённого примера |
| Ресурс результата | XML доступен по ссылке; содержимое не включается в краткий ответ инструмента |
| Сохранение файла | Байты результата задания совпадают с экспортным файлом тестового процесса |
| Экспорт другого заказа | Задание Failed, результата нет |
| Недопустимый размер детали | Задание Failed, результата нет |
| Отмена ожидающего и активного задания | Оба Cancelled; ожидающее не запускает дочерний процесс |
| Превышение срока | TimedOut, результата нет |

В ходе проверки исправлен устаревший ответ `get_capabilities`: теперь он сообщает о необязательных координатах `x/y`, списке резов и принятой политике целочисленного представления размеров. Исправление выполнено после падающего регрессионного теста.

Выходные файлы тестового процесса и манифесты сохранены в `.cache/mcp-batch`. Это воспроизведённые примеры для проверки адаптера, а не новые решения восьми мебельных заказов. Оптимизация, геометрическая правильность и автоматическое управление установленной Астрой этим прогоном не подтверждены.

В текущем окружении обёртка `scripts/inspect.mjs` получила `spawn EPERM` при запуске дочернего Node. Сам Inspector успешно отработал при прямом вызове его CLI из PowerShell; свежие доказательства лежат в `.cache/inspector/current-*`. Изменять настройки Астры для этих проверок не потребовалось.
