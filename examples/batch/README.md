# Заказы для проверки MCP и Астры

Последний прогон выполнен в фоновом режиме на отдельных невидимых рабочих столах: [результаты восьми заказов](results/20261101-144530-00447bdc/README.md), [подробная проверка](../../docs/background-verification.md).

Это исходные заказы для мебельного производства. Все размеры деталей целые, единицы — миллиметры. Кромки не заданы, чтобы проверка раскроя не зависела от справочника кромок. Существующие пользовательские заказы не изменяются.

| Файл | Проверка | Запрошено | Ожидается размещено | Ожидается не размещено |
| --- | --- | --- | --- | --- |
| 01-shelves.xml | Несколько одинаковых полок | 6 | 6 | 0 |
| 02-cabinet.xml | Корпус шкафа, несколько размеров | 8 | 8 | 0 |
| 03-two-materials.xml | Два материала, толщины 16 и 3 мм | 7 | 7 | 0 |
| 04-rotation-required.xml | Деталь помещается только после поворота | 1 | 1 | 0 |
| 05-rotation-forbidden.xml | Поворот запрещён; маленькая деталь помещается | 2 | 1 | 1 |
| 06-oversize-part.xml | Одна деталь больше листа | 3 | 2 | 1 |
| 07-many-copies.xml | Серия деталей на нескольких листах | 24 | 24 | 0 |
| 08-repeated-numbers.xml | Одинаковый номер в разных сборках | 5 | 5 | 0 |

Точные ожидаемые количества перечислены в [manifest.json](manifest.json). Число карт заранее не фиксируется: сравниваются допустимость результата и количество физических деталей, а не совпадение решений разных алгоритмов. Частичное решение с явно указанным остатком спроса допустимо для случаев 05 и 06.

Повторная генерация: `node scripts/generate-orders.mjs` из корня AstraMcp. Генератор перезаписывает только восемь исходных XML и manifest.json; результатов раскроя он не создаёт.

Для ручной проверки импортируйте заказы отдельно и экспортируйте рассчитанные результаты в отдельный каталог, например `examples/batch/results`. Не перезаписывайте исходные файлы. Дальше результаты можно проверить по именам заказа, материалам, деталям, допустимым поворотам, количествам и явным исходным листам. Наличие координат зависит от экспортного режима Астры.

Автоматический тест `McpBatchTests` отправляет все восемь XML в `validate_order` настоящего stdio MCP. Отдельные сквозные тесты очереди используют `NativeFixture.exe`, который воспроизводит известный XML для проверки жизненного цикла; это не расчёт восьми заказов Астрой. Их результаты помечены как replay fixture и сохраняются в `.cache/mcp-batch`.

Реальный прогон через установленную Астру завершён успешно: [итоговый каталог](results/20261101-113120-2d07f9e5/README.md), [JSON-отчёт](results/20261101-113120-2d07f9e5/report.json). Получены 11 физических листов, 54 размещённые детали и 2 ожидаемые неразмещённые. Координаты всех 54 размещённых деталей и 95 отрезков резов проверены отдельным .NET-верификатором.

Повторить реальные расчёты: `dotnet run --project tools/Verification/Verification.csproj -- . config.json` из корня репозитория. Неизменённые native XML, входные данные и логи сохраняются в новом каталоге `results/<run>`.
